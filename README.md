# dependency-manifest 1.0

Общий JSON-формат передачи наблюдаемых зависимостей от анализатора в каталог.
Он не привязан к HDL, MCP или конкретному расположению Git-репозиториев.
Машинный контракт: `schema.json`. Реальный пример hdl-order: `examples/hdl.json`;
файлы, по которым он построен: `examples/rtl/`.

## Семантика

`dependent` — зависимый объект; `dependency` — объект, от которого он зависит.
Ребро `{dependent: "top", dependency: "child", relation: "hdl.instantiates"}`
означает: top использует child. Для порядка сборки child предшествует top.
Для оценки последствий изменения child обход идёт в обратном направлении — к top.
Названия source/target для концов ребра не используются. `sources` означает только
логические корни файлов, не направление зависимости.

## Поля

| Поле | Назначение |
|---|---|
| format / version | `dependency-manifest` / `1.0` |
| producer | Имя и версия экспортёра, идентификатор анализатора |
| scope | Проект, профиль, область анализа и влияющая на результат конфигурация |
| sources | Логические корни; необязательная revision для диагностики |
| nodes | Файлы, символы и явно внешние/неразрешённые объекты |
| edges | Наблюдения с dependent, dependency, типом relation и необязательным evidence |
| coverage | Полнота, покрытые файлы, семейства отношений, ограничения |
| diagnostics | Сообщения info/warning/error с машинным кодом |

Файл содержит id, source, относительный path и content_hash `sha256:<hex>` точных
байтов. Символ содержит id, name, file, attributes и необязательный line (с 1).
Внешний объект содержит id, name и необязательный uri. Он не даёт права чтения URI.
Evidence указывает файл, точность file/symbol/line и необязательную строку.
Идентификаторы узлов уникальны в отчёте. Они не обязаны совпадать с ID каталога.

Корни отображаются в репозитории отдельным аргументом импорта; абсолютные пути
не переносятся. Запрещены выход за корень и неоднозначные дубли расположений.
Хеши сверяются со снимком потребителя. Revision не заменяет такую сверку.
JSON Schema проверяет форму. Дополнительный семантический валидатор проверяет
ссылки, уникальность, соответствие узлов покрытию и допустимость complete.
Эталонная реализация валидатора находится в OKF Workspace `src/manifest.ts`.

## Полнота и владение наблюдениями

`partial` позволяет добавлять наблюдения и обновлять метаданные, но отсутствие
ребра не удаляет прежнее наблюдение. `complete` разрешает заменить только
наблюдения того же источника, для перечисленных зависимых файлов и перечисленных
relation_types. Символьное ребро проецируется на содержащий символ файл.
Наличие error или внешних неразрешённых узлов несовместимо с complete в версии 1.0.
Пустой список relation_types не означает «удалить все отношения».

В OKF Workspace источник наблюдений определяется producer.name, producer.analyzer
и полным scope, включая конфигурацию. Версия экспортёра не создаёт новый источник.
Другие профили и ручные связи сохраняются независимо. Изменение конфигурации
создаёт другой источник; автоматическое удаление старого профиля не выполняется.
Повтор того же отчёта не порождает повторные причины пересмотра.

## Границы версии

Формат не утверждает актуальность документации и не содержит команд её изменения.
Связь документа с описываемым файлом и ссылки на главы управляются каталогом.
Нет эвристического сопоставления переименований, SemVer-диапазонов зависимостей,
автоматического исполнения анализатора или скачивания внешних объектов.
Неизвестные поля отклоняются; расширение контракта требует согласованной версии.

## Проверка

Пример экспортирован hdl-order 0.6.0 и проверен JSON Schema. Интеграционный тест
OKF Workspace 0.2.0 выполняет экспорт реального HDL-проекта, проверку хешей,
импорт графа и построение задач на создание карточек.
